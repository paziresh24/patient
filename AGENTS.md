# patient (paziresh24.com)

Patient-facing appointment booking site. Next.js 14, **pages router** (`src/pages`), TypeScript strict. 99% of traffic is mobile — design mobile-first, desktop is a wrapper. Persian/RTL throughout.

## Running it

`npm run dev` does **not** run plain `next dev` — it runs a custom `server.js` that boots an **HTTPS** server and requires local TLS certs:

```
npm run mkcert-localhost   # needs `mkcert` installed; generates cert/localhost-*.pem
npm run dev                # https://localhost (or https://local.paziresh24.com)
```

Without the certs, `server.js` logs an error and refuses to start — it does not fall back to HTTP. `npm run dev:turbo` sets a custom `TURBO=1` flag read inside `server.js` — not the same as Next's built-in `--turbo`.

Other scripts: `build` (runs `scripts/remove-google-fonts.js` first, then `next build`), `lint` (`next build` does **not** lint — `next.config.js` sets `eslint.ignoreDuringBuilds: true`, so run `npm run lint` separately), `test` (Jest, **watch mode by default** — use `test:ci` for a single run), `storybook`.

## Stack

Zustand (per-module stores) + React Query + SWR (both present, react-query for most new code) + Axios. UI: Ant Design, Radix, Tailwind (+`tailwindcss-rtl`). Plasmic is deeply integrated (29 projects wired in `plasmic.json`). Also: Sentry, Firebase (FCM), GrowthBook, `next-translate` (i18n, `locales/`), Matomo + GTM analytics.

## Where code goes

- `src/modules/<feature>/` — feature modules (booking, search, dashboard, profile, ravi, hamdast, …), each with its own `components/`, `hooks/`, `store/`, `types/`. **New feature logic goes here**; `src/pages/*.tsx` should stay a thin wrapper importing from the matching module.
- `src/common/components/atom/<name>/` — shared/generic components, pattern: `<name>.tsx` + `<name>.spec.tsx` + `index.ts`.
- `src/common/{apis,hooks,utils,constants,types}/` — shared cross-cutting code.
- Path aliases (`tsconfig.json`): `@/modules/*`, `@/common/*`, `@/components/*`, `@/utils/*`, `@/constants/*`, `@/hooks/*`, `@/apis/*`, `@/firebase/*`. Note `@/images/*` and `@/store/*` are declared but their target dirs don't exist — dead aliases, modules keep state in their own `store/` instead.

## Plasmic — critical boundary

- `.plasmic/plasmic/**` files are **auto-generated, never hand-edit** (`// This class is auto-generated by Plasmic; please do not edit!`). Re-synced via `npm run plasmic-sync` (needs `PLASMIC_PROJECT_TOKEN`).
- `.plasmic/<Name>.tsx` (outer skeleton files) **are meant to be edited** — generated once, then yours.
- `hamdast.js` (repo root) registers Plasmic components for the embeddable "hamdast" widget system (`@hamdast/Bimehnama`, `Cywoc24`, `Hamyar`, etc.) — ties into `src/modules/hamdast/` and `src/pages/_/` (a literal `_` directory: `apps/`, `chats/`, `myapps/`, `pricing/`, `services/` — the widget marketplace section).

## Config

Env vars are surfaced via `next.config.js`'s `publicRuntimeConfig`/`serverRuntimeConfig`, not just `NEXT_PUBLIC_` prefixing — much of the code reads config via Next's `getConfig()`, not `process.env` directly. `.env.example` lists required vars (backend base URLs, Sentry, GrowthBook, Firebase, Plasmic token). CONTRIBUTING.md references a `.env.development.example` that doesn't currently exist in the repo — don't rely on it.

## CI / remotes

Three remotes: `origin` (github.com, canonical push target), `gitlab` (gitlab.paziresh24.com), `hamgit` (hamgit.ir). A GitHub Action force-syncs pushes to GitHub `main` into the GitLab mirror and triggers a GitLab pipeline there, which builds/pushes a Docker image and calls an n8n webhook. Plasmic sync runs as a separate `repository_dispatch` GitHub Action that can auto-open PRs. Know which remote you're pushing to — pushing GitHub `main` cascades into an external pipeline.

## Testing

Jest + React Testing Library, `.spec.tsx` naming, colocated with source. Coverage is thin and uneven — concentrated almost entirely in `src/common/components/atom/*` and `src/modules/rate-and-review/`. Most modules (booking, search, dashboard) have no tests. No E2E runner.

## Gotchas

- **Husky hooks are not actually installed** — `.husky/` has no `pre-commit`/`commit-msg` file despite `package.json` defining `lint-staged` + `commitlint.config.js`. Don't assume commits get auto-linted locally.
- `middleware.ts` is currently a no-op stub — no request-level logic runs there.
- `legacy-peer-deps=true` in `.npmrc` — dependency tree may have version mismatches that npm won't flag.
- `README.md`'s "Technologies Used" list is stale (omits Plasmic, Sentry, Firebase, GrowthBook, Storybook). Don't treat it as authoritative.
- CONTRIBUTING.md has two small inaccuracies: says PRs merge into "master" (actual default branch is `main`), and cites `https://localhost:8766` (actual `server.js` default is port 443/`$PORT`).

## Persian/RTL responses (from `.cursor/rules/rtl-persian.mdc`)

When the user writes Persian, reply in Persian using `<div dir="rtl" lang="fa">` semantics; keep code blocks, paths, and terminal commands LTR. Respect this project's `dir="rtl"`, `text-right`, and Tailwind `rtl:`/`ltr:` conventions in any UI you touch.
